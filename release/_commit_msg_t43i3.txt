feat(nodelist): surface branches/releases from raw_json (T43i.3)

用户「云端其实是有这个功能,只是没有写入」+ AskUserQuestion 选 B 方案:
不写 SQLite 新列,前端 NodelistViewModel 直接 JSON.parse(raw_json) 拿 branches/
recentReleases/releaseCount/latestRelease 4 字段,UI 加显示。

## 背景

github.pudafo.com /api/v1/repos/{owner}/{repo} 实际返回嵌套 `repository.*`,
里面至少有:
- `branches[]` — 94.6% (5564/5883) entry 有
- `releaseCount` — 直给 int
- `recentReleases[]` — 10.5% (616/5883) entry 有
- `latestRelease` — object(常 null,但 API 字段在)

但 NodeRepoQueryService.Parse 只解析 14 个字段(stars/forks/.../topics),
branches/recentReleases/releaseCount/latestRelease 全部丢弃。
当前 nodelist_details.version 列存的是 `defaultBranch`(如 "main"),
不是 release tag。

## 方案对比

| 方案 | 描述 | 代价 |
|---|---|---|
| A. Parse + schema 加 4 列 | ALTER TABLE + 重 fetch + 改 version 主键语义 | 大 |
| B. 懒解析 raw_json | 前端 VM 直接 JSON.parse(raw_json) | **小,选这个** |
| C. 只改 version | 只覆盖 defaultBranch → releaseCount[0].tag_name | 中 |

B 方案立即生效,老 DB 不用迁移,raw_json 在 nodelist_details 已有(T43h)。

## 改动

- NodelistViewModel.cs (DetailRow POCO +123 行):
  - 加 4 属性:`LatestReleaseTag` / `ReleaseCount` / `BranchNames` / `RecentReleases`
  - 加 `RefreshFromRawJson()` public 方法:从 RawJson 解析 4 字段
  - 加 `ParseRawJson(string?)` private static:走 repository.* → root fallback
    (兼容自定义 API + GitHub 原生),Null/空/非 JSON/无 repository → 全部空值
  - `ParseRawJson` 内部细节:
    - branches[] → 只取 .name(其他字段 commit_sha/protected 暂不用)
    - recentReleases[] → "{tag_name} (YYYY-MM-DD)" 前 10 字符日期
    - releaseCount 缺失 → 兜底 recentReleases.Count
    - latestRelease.tag_name 优先 → fallback recentReleases[0].tag_name
  - RefreshSelectedDetails line 593+:每个 DetailRow.Add() 之后调 RefreshFromRawJson()

- NodelistView.xaml (+44 行):
  - 详情 card 统计 WrapPanel(line 386 后)加 2 TextBlock:
    "🏷 Latest: {tag_name}" + "📦 Releases: {count}"
  - 现有 Topics ItemsControl 后加 2 个 ItemsControl:
    "🌿 分支:" + TagPillBorder pills(branch name)
    "🚀 最近版本:" + TagPillBorder pills("{tag} ({date})")

## 不改的东西

- ❌ SQLite schema:0 列新增 / 0 列删除
- ❌ NodeRepoQueryService.Parse:仍然只解析 14 字段(branches/releases 留 raw_json)
- ❌ Ingestor:仍然只走 Parse 流程
- ❌ 老 DB migration:0 改动(数据库结构不变)
