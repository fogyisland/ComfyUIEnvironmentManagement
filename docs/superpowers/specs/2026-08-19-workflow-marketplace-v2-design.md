# Workflow Marketplace v0.6.22 — CivitAI 模型端点切换 + 搜索栏 UI 重设计

> **Status:** DRAFT — awaiting user review before plan/implementation.
> **Complements:** v0.6.19 (`docs/superpowers/specs/2026-08-18-workflow-marketplace-design.md`, SHIPPED `b110f86`) — same workflow marketplace plumbing. v0.6.22 fixes the **CivitAI source endpoint** to use the model-centric endpoint `/api/v1/models?types=WORKFLOW` (instead of `/api/v1/images?tags=workflow` image-scraping path that surfaced the v0.6.19 final-review Critical bug where missing `meta.workflow.workflowJson` field caused binary image bytes to be written as `workflow.json`), and redesigns the search bar to look + feel like a search UI.

**Goal:** The CivitAI workflow source returns proper model entries with `modelVersions[].files[].downloadUrl` for `.json` files (instead of unreliable image-metadata scraping). The workflow view's top toolbar makes the search affordance unmistakable — 🔍 icon + clear button + visible "搜索" label + wider input — so users perceive it as a search UI from the first glance.

**Architecture:** T1 replaces `CivitAiSource.SearchAsync` to call `/api/v1/models?types=WORKFLOW&sort=models.donated&limit=N` and parse `items[].modelVersions[0].files[]` to find the `.json` workflow file. New internal DTO classes `CivitAiModelResponse`/`CivitAiModelVersion`/`CivitAiModelFile` (kept `internal` so test seam can access them via `InternalsVisibleTo`). T2 restructures `Views/WorkflowMarketplaceView.xaml` Row 0 toolbar — replace the bare `TextBox` with a `SearchBox`-style composite control: 🔍 icon (Path, no emoji per v0.6.17.1) + `<TextBox>` + `✕` clear button visible when text non-empty + label "搜索" or placeholder text.

**Tech stack:** Same as v0.6.19 (WPF .NET 8 / C# 12 / xUnit / SQLite / `HttpClient` singleton). **No new sub-systems** — T1 is internal refactor of `CivitAiSource` + tests; T2 is pure XAML polish.

**base SHA:** `a21d9dd` (post v0.6.21 — current HEAD).

## 1. Background & user request

### v0.6.19 Critical bug recap

`CivitAiSource.cs:36` used `GET /api/v1/images?tags=workflow` which returns *images* (not workflow models). Each image has a `meta.workflow.workflowJson` URL field — but only some images have it (the ones generated by ComfyUI with embedded workflow). When the field was missing, v0.6.19 T4 originally had a `??=` fallback to `item.url` (the image URL itself) which was a **Critical bug** — `WorkflowDownloader` would write binary image bytes to `workflow.json`, corrupting production data.

v0.6.19 fix-wave R1 `b110f86` removed the fallback (5 lines), so missing `workflowJson` now means "skip this entry". But this means **many entries are silently dropped** because the image-source endpoint doesn't reliably expose workflows.

### User-clarified direction

> "工作流界面和设置似乎有些问题。参考下 [...CivitAI 工作流 API...]: GET `https://civitai.com/api/v1/models?types=WorkFlow`"
> "目前搜索按钮都没有，感觉界面也不像个搜索界面"

Two concrete asks:
1. **Switch CivitAI endpoint** to model-centric `/api/v1/models?types=WORKFLOW` — gets the right data shape (models with versioned workflow JSON files).
2. **UI search affordance** — current `TextBox` with no icon / no label / no clear button doesn't register as search. Add 🔍 + clear + label/placeholder.

### User decisions (during brainstorm)

- **Endpoint URL**: `/api/v1/models?types=WORKFLOW` (CivitAI's documented model type for workflow entries).
- **Sort**: `Most Downloaded` (default per CivitAI for workflows).
- **File selection**: Pick the first `.json` file from `files[]` (workflow JSON typically named `workflow.json` or `<slug>.json`).
- **UI**: Add `🔍` Path icon + `✕` clear button + visible "搜索" placeholder text. No emoji per v0.6.17.1 WPF font fallback lesson.
- **Scope**: v0.6.22 covers ONLY T1 (endpoint) + T2 (UI polish). PNG metadata extraction (BitmapDecoder for tEXt chunks) + missing-node detection + `/prompt` POST integration are deferred to v0.6.23+.

## 4. Architecture

### 4.1 T1: CivitAI source endpoint migration

#### Current `CivitAiSource` (v0.6.19)
```
GET /api/v1/images?tags=workflow&sort=Newest&limit=N
↓
items[]: {
  id, name, username, url, meta.workflow.workflowJson  // only some images have meta.workflow
}
↓
WorkflowEntry { WorkflowJsonUrl = meta.workflow.workflowJson, PreviewImageUrl = item.url }
```

#### Target `CivitAiSource` (v0.6.22)
```
GET /api/v1/models?types=WORKFLOW&sort=models.donated&limit=N
↓
items[]: {
  id, name, creator.username, tags[],
  modelVersions[]: {
    id, files[]: { name, downloadUrl },
    images[]: { url }
  }
}
↓
WorkflowEntry {
  Title = name,
  Author = creator.username,
  Tags = tags[],
  WorkflowJsonUrl = first .json file's downloadUrl,
  PreviewImageUrl = first image's url,
  SourceUrl = {baseUrl}/models/{id}
}
```

#### DTO classes (new, internal)

```csharp
// in same file as CivitAiSource.cs OR in Services/WorkflowSources/CivitAiModels.cs

internal sealed class CivitAiModelResponse
{
    [JsonPropertyName("items")]
    public List<CivitAiModelItem> Items { get; set; } = new();
}

internal sealed class CivitAiModelItem
{
    [JsonPropertyName("id")] public long Id { get; set; }
    [JsonPropertyName("name")] public string Name { get; set; } = "";
    [JsonPropertyName("creator")] public CivitAiCreator Creator { get; set; } = new();
    [JsonPropertyName("tags")] public List<string> Tags { get; set; } = new();
    [JsonPropertyName("modelVersions")] public List<CivitAiModelVersion> ModelVersions { get; set; } = new();
}

internal sealed class CivitAiCreator
{
    [JsonPropertyName("username")] public string Username { get; set; } = "";
}

internal sealed class CivitAiModelVersion
{
    [JsonPropertyName("id")] public long Id { get; set; }
    [JsonPropertyName("files")] public List<CivitAiModelFile> Files { get; set; } = new();
    [JsonPropertyName("images")] public List<CivitAiModelImage> Images { get; set; } = new();
}

internal sealed class CivitAiModelFile
{
    [JsonPropertyName("name")] public string Name { get; set; } = "";
    [JsonPropertyName("downloadUrl")] public string? DownloadUrl { get; set; }
}

internal sealed class CivitAiModelImage
{
    [JsonPropertyName("url")] public string Url { get; set; } = "";
}
```

#### File selection helper

```csharp
private static CivitAiModelFile? PickWorkflowJsonFile(IEnumerable<CivitAiModelFile> files)
{
    return files.FirstOrDefault(f =>
        !string.IsNullOrEmpty(f.DownloadUrl) &&
        f.Name.EndsWith(".json", StringComparison.OrdinalIgnoreCase));
}
```

If `modelVersions[0]` is empty OR no `.json` file in `files[]` → skip the entry (matches existing v0.6.19 fix-loop R1 "skip on missing" semantic).

**Placeholder behavior**: WPF `<TextBox>` doesn't have built-in placeholder. Two options:
- (a) Add a TextBlock overlay with Visibility bound to inverse of `HasSearchText` (simple, fits existing patterns).
- (b) Add a custom `SearchTextBox` user control (overkill for v0.6.22).

**Decision**: Option (a) — overlay `<TextBlock Text="搜索工作流" IsHitTestVisible="False">` with `Visibility="{Binding HasSearchText, Converter={StaticResource InverseBoolToVisibility}}"`.

## 9. Risks

- **CivitAI API rate limit (60/h no token)** — same as v0.6.19. Settings has `WorkflowSourceCivitAiEnabled` toggle to skip if user hits limits.
